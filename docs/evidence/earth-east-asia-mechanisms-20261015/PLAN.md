# 东亚降水机制拆分与浮力对流修复

用户授权：检查并修改上一轮发现的东亚缺雨、雨季偏差。基线 104e7fe；前轮证据只读。本轮不预设新默认参数必须通过，也不将区域总量吻合等同于季风正确。

1. 同正式第零天库存、完整地形，分开运行 control / transport-only / radiation-only / shared-core。拆分水汽求解与空气辐射份额 0.5 的影响，避免将上轮组合差异误归给一个机制。
2. 检查旧浮力对流实验中日照乘子：表面仍暖、空气湿润却在无日照时完全无对流。新增无日照案例，验证暖湿、有浮力时成雨，稳定或干燥时不成雨，水量与潜热闭合；旧行为下已观察到失败。
3. 只在已有 buoyantConvection 实验开关下移除重复日照限制；旧缺省及 false 分支保持原算式。浮力触发依赖地表相对空气的温差与有限水汽；不添加区域、月份或 GPCC 修正系数。
4. 对相同 shared-core 背景运行 buoyancy-old（旧开关实现）及 buoyancy（修复后），从而分别量化既有温度门槛变化与本次日照门槛修复的效果。
5. 将开关接入水循环面板，保留可见状态与预算起点，完整存档可严格续跑。以实际 DOM 检查播放中切换。
6. 检查东亚六区及七个外区的月雨量、年雨量与峰月；同库存、物理一年、所有降水分项、预算和严格续跑均需通过。若区域季节规律仍失败，明确保留失败结果，不宣称已修好季风或更改正式地球默认。

方法依据：成熟对流方案以条件不稳定、湿度及垂直热力状态判断触发；[SPEEDY 源码](https://pyspeedy.readthedocs.io/en/latest/speedy_f90/sourcefile/convection.f90.html) 可见 diagnose_convection 和有限质量通量过程。当前单层模型缺少这些完整垂直状态，本次仅修正其浮力实验内部的重复日照门槛，不声称实现 SPEEDY、CAPE/CIN 或真实对流云。
