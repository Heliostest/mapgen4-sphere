# 第二部分实现与验证约束

用户已指定目的、范围与自动发布流程。本轮按已授权范围实施，先查根因，再以数据、守恒回归和连续积分验证。

1. 数据：只接受一手来源的独立冰厚与 grounded/shelf 掩膜；ETOPO 冰面继续作为地表，不用 surface−bed 差冒充浮冰架厚度。数据采样至现有 96×49 地表层，来源、缺测、边缘、单位、投影、许可及校验记录随场景。
2. 库存：可选配置接入真实 grounded 冰，替代该场景温度阈值猜测的冰盖。分配现有水库，记录初始总水与焓；浮冰架用独立库存，融水回海洋；陆地冰融水进入原径流。基岩与表面高程分别使用，不能重复叠加冰厚。
3. 热储层：可选 `separateReservoirs` 使空气、陆地与海洋具有各自温度和热容量；相变只限制相应储层，换热和潜热有明确归属，完整预算含各层。默认关闭以保留旧档和程序星球行为。
4. 存档：新字段严格解码、检查尺寸与掩膜、质量与能量账本；缺少可选字段的旧档保留原路径。回滚与恢复必须保留三个热层和全部冰库存。
5. 证据：固定 be74609 基线，同地形、同参数、同镜头，第0天和连续实际积分约170/350天。南极、格陵兰、北极海冰、南大洋海冰、青藏/喜马拉雅逐区统计；严格区分即时参考和连续积分。
6. 浏览器：8002场景恢复离线完整存档、实际播放/暂停，检查冰缘、融合地表、径流湖泊与诊断，不干扰8000/8001。
7. 完成：独立代码审阅及物理/视觉证据核对，修复后运行测试、typecheck、build、Earth verify、GPU相关回归、diff检查；自动提交、合并main、正常推送origin并核对一致。

本轮不实现热带降雨、河网闭流盆地或分辨率升级；数值守恒不等同地球气候校准。
